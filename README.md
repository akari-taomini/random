# 桃mini · 同义随机宏工坊 v1.3.0

给同一句提示词准备几种意思相近的说法。导回酒馆后，每次聊天会随机选一种。制作这些新说法时需要调用 AI；以后聊天时随机抽取，不额外调用一次改写 AI。

## 第一次用，举个普通句子的例子

假设原来的提示词是：

> 请使用中文回答问题，并尽量表达得简洁清楚。

让 AI 另外写 3 种说法，例如：

- 回答问题时请用中文，尽量把话说得简洁明白。
- 请以中文作答，表达尽量简洁易懂。
- 请用中文回答问题，并尽量做到言简意明。

保留原文后，就有 4 种说法。导入新预设后，酒馆每次随机选一种发送，也可能连续选中同一种。插件会帮你做好随机选项，无需手动拼接。

这些只是说明用的文字。插件首页的“第一次用？点这里看教程和例子”也有同样的示例，展开阅读不会调用 API 或改动预设。

## 照着这 4 步做

1. **选谁来改写。** 在第 1 步选择“用酒馆里保存好的 API（推荐）”，再选一个已保存的连接。没有连接时，先去酒馆“API 连接”面板保存一份“连接预设”，回来点“更新列表”。其他数字先不改。
2. **选要改的文字。** 在第 2 步点“读取酒馆当前预设”，勾选想处理的提示词。这里的“条目”就是预设里的一条提示词，可以先只选一项试试。灰色项会原样保留。
3. **生成并选用。** 点“开始生成新说法”。完成后查看结果，满意就点“全部用上”，或者逐段勾选“用这一组新说法”。不满意的可以点“再写一组”。
4. **导回酒馆使用。** 点“下载改好的预设”，然后去酒馆“对话补全预设”面板导入这个 JSON 文件，再选中它使用。只下载文件还不会自动生效。

上面选的 API 是“谁来改写”，下面读取的预设是“要改哪些文字”，两者可以不同。

想下次继续，点“保存进度”；下次点“继续上次进度”选择进度文件。进度文件用于继续编辑，不是直接导入酒馆聊天的预设。

## 不懂这些设置时，先用默认值

| 界面选项 | 是什么意思 | 默认值 |
| --- | --- | --- |
| 每段另外写几种说法？ | 填 3 就是新增 3 种，保留原文后共有 4 种 | 3 |
| 一次合并几段发送？ | 把多段文字一起发给 AI，减少请求次数 | 5 |
| 每分钟最多请求几次？（RPM） | 按接口的频率限制控制发送速度，要给聊天留些额度；0 表示不限 | 10 |
| 原来的句子也保留 | 聊天时原文也有机会被随机选中 | 勾选 |

这些选项收在“可选：调整数量和速度（不懂先不改）”里，当前设置会显示在外面。比如 20 个短段落、每次合并 5 段，通常只需 4 次请求；长段落会自动减少同批数量。

## 版本更新

v1.3.0：插件内加入普通句子示例、四步新手教程和常见问题；按钮与提示改成更直白的说法；数量和限速收进可选区域，随时可展开调整。

v1.1.0 新增：选择酒馆 API 连接预设、显示该连接的模型、刷新连接列表，通过酒馆后台请求；无需重复填写密钥，不切换当前聊天连接。

v1.1.1 新增：“全部用上”和“取消全部选用”。作用于当前工作区所有条目，不受搜索或条目勾选影响；一键采用仅处理已生成且校验通过的段落，失败或未生成的段落保留原文。取消采用不会删除生成结果。

v1.2.0 新增：多段合批、预计请求数、RPM 限速与限流冷却。默认每次最多 5 段、每分钟最多 10 次生成请求；每批段落数可设为 1～50，RPM 可设为 0～600（0 表示不限）。

v1.2.1 修复：“读取酒馆当前预设”误用酒馆通用预设读取函数而拿到空对象。现在优先读取当前界面的对话补全设置（含尚未保存的提示词修改），结合已保存预设保留元数据；旧版上下文可回退至酒馆对话补全模块。界面会标注“当前界面状态”或“已保存版本”。

## 安装

推荐通过 Git 地址安装：打开酒馆“扩展 → 安装扩展”，粘贴以下地址并安装，随后刷新页面：

```text
https://github.com/akari-taomini/random.git
```

在“扩展”设置面板点击“🍑 打开同义随机宏工坊”。以后可在酒馆扩展管理中检查更新。

### 手动安装源码包

这是插件源码压缩包，不是预设 JSON，也不是酒馆助手脚本。解压后将 `taomini-preset-variants` 文件夹放入酒馆的扩展目录，确保 `manifest.json` 直接位于该文件夹内，不要多套一层文件夹。

- 通常可放入 `SillyTavern/data/default-user/extensions/taomini-preset-variants/`；多用户安装请把 `default-user` 换成实际用户目录。
- 也可使用公共扩展目录 `SillyTavern/public/scripts/extensions/third-party/taomini-preset-variants/`。
- 刷新酒馆，在“扩展”设置面板点击“🍑 打开同义随机宏工坊”。没有出现时，确认扩展已启用并检查目录层级。

有服务器文件管理器时可上传解压；在 Termux 部署时用文件管理器或 `cp -r` 复制到对应目录。无需 npm install，无需构建，无需额外后端。酒馆的“通过 Git 地址安装扩展”使用上方仓库地址，不能直接填 ZIP 地址。使用 GitHub 下载的源码包时，解压目录可能叫 `random-main`，可重命名为 `taomini-preset-variants` 后按上述路径安装。

## 生成与保存的小提示

- “开始生成新说法”只处理还没生成的部分；已有结果想重写，点对应段落的“再写一组”。
- “只重试失败的”只处理勾选提示词中的失败部分，并会继续合批发送。
- “全部用上”作用于这次工作区所有成功生成的结果，不只是当前查看的那项。没有选用的部分保持原文。
- 编辑新说法或重新生成后，需要重新勾选“用这一组新说法”。
- “取消全部选用”不会删掉新说法，之后可以重新选择。
- 生成停止后，已完成的结果会保留。刷新页面前想保留进度，请先停止生成，再点“保存进度”。
- 按钮下会显示已读取的预设名称、提示词数量和数据来源。如果标注“已保存版本”，请先在酒馆保存最新修改，再重新读取。

### 请求次数与限速的详细说明

每个可改写的非空行作为一段，不同段落可以跨提示词合并发送。每次请求会生成该批所有段落的新说法，不是每种说法分别请求一次。设每次合并 1 段，就会逐段发送。

为降低输出截断风险，程序会按文本长度和新说法数量控制同批大小。文字越长、生成的说法越多，同批段落越少，所以预计请求数可能多于“总段落数 ÷ 每批上限”。超长单段会单独发送，仍可能触及模型输出限制；可以减少新说法数量后重试。

一批内某段失败或漏回时，成功的部分仍保留。“只重试失败的”只把失败部分重新合批；不会自动拆成大量单段请求。

可识别的 HTTP 429 或 5xx 最多自动重试一次。429 响应有可读取的 Retry-After 时按该值等待，否则默认等 60 秒；5xx 至少等待 1.8 秒。重试也遵守本工坊的 RPM 间隔，等待时可以停止。再次点生成或重试不会清除等待时间。

限速仅统计本工坊当前页面，其他聊天、插件或页面还会占用接口额度。刷新页面会重置本地计时。合批减少请求次数，但仍会消耗生成文字的额度，也可能受接口的 token 限制影响。

## 使用酒馆 API 连接预设

“酒馆 API 连接预设”指酒馆 API 连接面板中的 **Connection Profiles**，用于保存 API 类型、模型、地址、密钥选择和相关生成预设。它与下方“要改写的聊天补全预设”分别选择：可以用连接 B 来改写当前预设 A。

1. 在酒馆“API 连接”面板配置好接口和模型，并保存为一个连接预设。
2. 工坊的“用哪个 AI？”选择“用酒馆里保存好的 API（推荐）”。
3. 点击“更新列表”，选择连接名称与模型，直接生成；无需重填地址或密钥。

此模式使用酒馆官方 `getContext().ConnectionManagerRequestService`，沿用该连接的模型、地址、密钥选择、代理配置及接口支持的关联生成参数。支持的聊天补全、文本补全连接由酒馆接口筛选；文本补全可使用连接保存的指令模板。不切换全局连接，不修改聊天，也不附带聊天历史、角色卡、世界书或聊天补全预设的指令正文。发送内容为工坊改写提示词和选中文本，由酒馆执行必要的接口格式化。

此模式经酒馆后台发起请求，不要求上游 API 支持浏览器跨域；仍需保证酒馆服务器能访问接口并具备有效凭据。插件只保存所选连接 ID，不复制密钥。运行中删除所选连接会停止后续请求，不会自动改用其他连接。

如果列表为空，请先保存连接并确认“连接预设”扩展已启用，再刷新。若提示当前酒馆未提供请求接口，需要更新酒馆，或改用单独填写 API；本插件不会通过临时切换全局连接来兼容旧版。

## 单独填写 API：地址示例

| 接口格式 | 基础地址写法 |
| --- | --- |
| OpenAI 兼容 | `https://你的服务/v1`，或服务给出的完整 `/chat/completions` 地址 |
| Gemini 原生 | `https://generativelanguage.googleapis.com/v1beta`，或兼容原生格式的代理基础地址 |

插件不会自动添加 `/v1`。如果服务要求 `/api/v1` 等路径，须完整填写。只支持无查询参数的 HTTP(S) 地址，不支持依赖自定义请求头的特殊服务。OpenAI 兼容格式使用 Bearer Key；Gemini 原生使用 `x-goog-api-key` 请求头。模型必须填写接口实际支持的 ID。

单独填写模式的请求从酒馆浏览器页面直接发往填写的接口，接口必须允许浏览器跨域（CORS）；HTTPS 酒馆页面访问普通 HTTP API 还可能被浏览器拦截。网络错误不代表提示词失效。服务若不允许浏览器直连，可改用酒馆 API 连接预设模式。

单独填写的密钥只保存在当前页面内存与密码输入框中，刷新即清空。其余 API 设置和自定义提示词保存到酒馆扩展设置。插件不会读取聊天历史、角色卡或密钥明文；酒馆连接模式由酒馆后台处理凭据。只发送选中段落和改写提示词。请求次数取决于段落数，正常使用会消耗所选接口的额度。

## 文本保护与已知范围

- 按原有行拆分，每个可改写的非空行作为一个语义单元；保留换行、缩进和列表前缀。单行超过 6000 字符时跳过，建议人工分段后再处理。
- 含已有酒馆宏的整行、跨行宏、代码块、HTML/XML 标签行、注释、链接、标题、表格、配置行、较短标识符及含花括号或 `::` 的行默认保留，界面可查看原因。
- 不把受保护内容还原后塞入随机宏内部，避免嵌套宏在不同酒馆版本里的解析差异。纯文本行即使位于 XML 容器内，也可独立改写，标签本身保留。
- 校验返回 JSON、段落 ID、变体数、重复、宏分隔符、换行与结构符号。结构校验不能证明语义等价，所以必须逐段审核采用。
- 这是单行文本变体生成器；不自动调整条目顺序、启用状态、角色、注入位置或其他生成参数。导出只替换已采用的 `content`。
- 宏按酒馆自身规则展开。相邻请求可能抽到同一选项；随机不代表每次一定不同。对任何模型的输出效果均需自行实测。

## 断点继续

“保存进度”导出原预设、变体、采用状态与选择列表；之后“继续上次进度”继续工作。草稿不包含本插件的 API 配置和密钥。关闭面板会收起界面，正在进行的请求继续运行；请使用“停止”明确停止。刷新页面前请先停止并导出草稿，刷新后未导出的工作会丢失。读取另一个预设或继续上次进度会替换当前工作区。

## 开发与验证

源码为原生 JavaScript ES 模块，无第三方运行依赖。`core.js` 负责规划、校验、独立 API 和导出，`batch.js` 负责合批和请求节奏，`st-api.js` 负责酒馆连接预设适配，`preset-reader.js` 负责读取酒馆当前预设，`index.js` 负责界面，`style.css` 负责自适应样式。

当前预设读取优先使用 `context.chatCompletionSettings` 和 `getCompletionPresetByName()` / `getPresetList()`，不会调用不支持聊天补全的通用 `getPresetSettings()`。需要时通过酒馆已加载的 `openai.js` 模块获得旧版导出；不会从提示词列表 DOM 抓取正文，也不会把整个运行时连接配置复制进新预设。

运行测试：`npm test`。可设置 `PRESET_FIXTURE` 为本地预设路径，额外验证真实预设往返完整性。测试中的 API 均为模拟响应；使用自己的 API 后仍需检查实机连接与输出。

浏览器模拟测试：在开发环境单独安装 Playwright 及 Chromium 后运行 `npm run test:ui`。也可用 `PLAYWRIGHT_MODULE_PATH` 指定 Playwright 模块路径、`BROWSER_EXECUTABLE_PATH` 指定已有 Chromium。此测试模拟酒馆上下文和 API，检查限流重试、变体编辑与采用、预设导出、草稿恢复、连接预设选择、所选连接失效、停止、全局连接保持及手机宽度布局；不等同于真实酒馆部署和付费 API 联调。
